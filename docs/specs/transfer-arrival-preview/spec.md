# 환승 도착 정보 미리보기

## User-visible outcome

사용자가 출발지·목적지 지명을 입력하면 각각에 가장 가까운 정류장/역이 추천되고, 그 두 지점을 잇는(환승 최대 2회) 경로를 안내받아, 출발역 아래에는 출발 시각을, 환승역마다 도착 예정 시각을(현재 시각 기준 추정치) 확인하고, 각 환승 지점에서 탈 다음 버스/지하철의 출발 예정 시간을 목록으로 확인할 수 있다.

## Scope

- 출발지·목적지 지명 입력 → 각 지명에 가장 가까운 정류장/역 추천 → 그 두 지점을 잇는, 환승 지점을 포함한 경로(구간들과 그 사이 환승 지점들) 안내
- 지명과 가까운 정류장/역의 매칭, 그리고 도착 정보는 모두 예시 데이터로 제공한다. 실제 지오코딩을 수행하지 않는다
- 1~9호선(4호선은 진접선·과천선·안산선 포함, 9호선은 전체) 실제 노선도 순서를 바탕으로, 어떤 두 역을 골라도 실제로 존재하는 환승역을 거치는 경로를 자동으로 찾는다. 노선을 그래프로 보고(두 노선이 역을 공유하면 그 역에서 환승 가능), 노선 단위로 너비 우선 탐색해 환승 최대 2회(노선 최대 3개)까지 경로를 찾는다. 같은 노선을 이미 공유하는 두 역을 고르면 애초에 환승이 필요 없는 구간이므로, 경로 대신 "환승이 필요 없다"는 안내를 보여준다. 1~8호선은 서울 도심 핵심 구간 위주로 간략화했다(아래 Constraints 참고)
- 위 9개 노선에 속하지 않는 지명(판교역 등 손으로 정한 예시)은 여전히 미리 정해둔 소수의 예시 조합으로만 경로가 나온다
- 경로찾기 버튼을 누르는 순간(현재 시각)을 출발역 시각으로 삼아, 각 구간의 예상 소요 시간만큼 누적해 각 환승역의 도착 예정 시각을 계산해 보여준다. 실제 열차 시각표를 조회하지 않고, 노선 순서를 아는 구간은 역 개수 기반으로, 손으로 정한 예시 조합은 미리 정해둔 소요 시간으로 추정한다
- 각 환승 지점에서 탈 다음 교통편(버스 또는 지하철)의 출발 예정 시각을 목록으로 보여준다. 환승 횟수와 관계없이 환승 지점마다 3개씩 보여준다. 각 시각은 도착 예정 시각에, 다음 구간 노선의 실제 배차간격을 참고한 환승 대기 시간(출퇴근·평시에 따라 다름)을 등간격으로 더해 계산한다. 환승이 2회인 경로는 두 번째 환승역부터는 첫 환승역에서 실제로 탈 열차(목록의 첫 값)를 탄다고 가정하고 이어서 계산한다
- 이동 수단은 버스와 지하철을 다룬다. 지하철은 운영 사업자를 가리지 않는다
- 추천 경로 화면에 "이전"·"다음" 버튼을 두어, 출발역에서 탈 열차 기준으로 출발 시각을 앞뒤로 옮겨볼 수 있다. 한 칸은 첫 구간 노선의 배차간격만큼이며, 이동하면 모든 환승역의 도착 예정 시각과 출발 예정 시각 목록도 함께 다시 계산된다. "이전"은 경로찾기를 누른 시각보다 앞으로는 가지 않는다
- 위치를 자동으로 추적하지 않는다. 사용자가 직접 확인 동작을 해야 도착 정보가 갱신된다 (PRODUCT.md 확정 사항)
- 경로나 이전 조회를 저장하는 계정·즐겨찾기 기능은 두지 않는다 (PRODUCT.md 확정 사항)

## Acceptance criteria

- 미리 정해둔 예시 지명 중 하나를 출발지에, 다른 하나를 목적지에 입력하면, 각각에 가장 가까운 정류장/역이 추천된다.
  - 예시 1: 출발지 "판교역"을 입력하면 "판교역.버스환승센터" 정류장이, 목적지 "잠실역"을 입력하면 "잠실역"이 추천된다.
  - 예시 2: 출발지 "여의도"를 입력하면 "여의도역" 정류장이, 목적지 "합정"을 입력하면 "합정역"이 추천된다.
- 추천된 두 지점을 잇는, 환승 지점을 포함한 경로가 화면에 표시된다. 구간은 버스 또는 지하철 구간일 수 있다 (예시 1의 경우 "판교역.버스환승센터"에서 버스 탑승 → "강남역"에서 하차해 지하철로 환승 → 2호선으로 잠실 방향 이동, 과 같은 흐름).
- 1~9호선에 속한 역 두 개를 출발지·목적지로 입력하면, 실제로 존재하는 환승역을 거치는 경로가 화면에 표시된다. 어떤 조합을 넣어도 동일하게 동작한다 (예시: "평촌역"(4호선)에서 "잠실역"(2·8호선)까지, "평촌역"에서 "도곡역"(3호선)까지, "모란역"(8호선)에서 "청량리역"(1호선)까지 — 마지막 예시는 환승 2회가 필요하다).
- 같은 노선을 공유하는 두 역을 입력하면, 경로 대신 "환승이 필요 없는 구간"이라는 안내가 표시된다.
- 경로가 표시될 때 출발역 이름 아래에 출발 시각(현재 시각)이 표시된다.
- 각 환승역 이름 아래에 도착 예정 시각이 표시된다.
- 환승 횟수와 관계없이 각 환승 지점에서 탈 다음 교통편의 출발 예정 시각이 3개씩 목록으로 표시되며, 뒤로 갈수록 시각이 늦어진다.
- 예시 데이터에 없는 지명을 입력했을 때의 동작(빈 결과, 안내 메시지 등)은 이번 acceptance criteria의 검증 대상이 아니다.
- 환승 3회 이상인 경로는 이번 범위에서 다루지 않는다(해당 시 "예시 경로가 아직 준비되어 있지 않다"는 안내로 처리된다).
- "다음" 버튼을 누르면 출발 시각과 모든 환승역의 도착 예정 시각이 늦어지고, 그 뒤 "이전"을 누르면 원래 출발 시각으로 돌아온다. 첫 조회 직후에는 "이전" 버튼이 비활성화된다.

## Constraints and rationale

- **환승 지점의 도착 정보는 실제 API가 아닌 노선별 배차간격 추정치로 채운다.** 실제 버스·지하철 도착정보 API(TAGO, 서울시 버스도착정보, 서울시 지하철 실시간 도착정보)는 공공데이터포털 개인 인증키가 있어야 호출할 수 있는데, 아직 발급받은 키가 없다. 처음에는 클릭할 때마다 무작위 값을 보여주는 방식으로 이 API 응답 스키마를 흉내 냈지만, 사용자 요청에 따라 노선별 실제 배차간격을 반영한 출발 예정 시각 목록(환승 지점마다 3개) 방식으로 대체했다.
- **지하철은 운영 사업자를 가리지 않고 다룬다.** 처음에는 서울교통공사 운영 구간만 다루다가, 사용자가 요청한 평촌역(코레일 과천선)·마곡나루역(서울시메트로9호선)이 서울교통공사 구간이 아닌 것으로 확인되면서 운영사 제한을 없앴다. 예시 데이터로만 동작하는 한 운영사 구분이 구현에 영향을 주지 않기 때문이다.
- **1~9호선을 노선 그래프로 보고, 두 역 사이에 실제로 존재하며 총 이동 역 수가 가장 적은(=가장 빠른) 경로를 자동으로 찾는다(환승 최대 2회).** 처음에는 4호선·9호선만 다루고 손으로 정한 소수의 예시 조합 외에는 실제 경로 탐색 엔진을 만들지 않기로 했었다. 그런데 사용자가 시도한 "평촌역-잠실역", "평촌역-도곡역" 조합이 이 범위 밖이라 경로를 찾지 못하는 걸 확인했고, 사용자가 1~9호선 전체와 환승 2회까지 지원하도록 범위를 넓혀 달라고 요청해 이번 범위를 다시 정했다. 처음에는 노선을 그래프의 노드로 보고 너비 우선 탐색으로 첫 번째로 찾은 경로를, 환승역도 두 노선이 공유하는 역 중 배열 순서상 먼저 나오는 역을 그대로 썼다. 이후 사용자가 최단 시간 기준 추천을 요청해, 환승 최대 2회(노선 최대 3개) 안에서 실제로 존재하는 모든 노선 조합과, 그 조합마다 두 노선이 여러 역을 공유할 때의 환승역 조합까지 전부 따져 총 이동 역 수가 가장 적은 조합을 고르도록 바꿨다. 예를 들어 평촌역(4호선)에서 도곡역(3호선)까지는 충무로역에서 1회 환승(총 32역)하는 경로보다, 사당역·교대역을 거쳐 2회 환승(총 16역)하는 경로가 더 짧아 후자를 추천한다. 다만 이 비교는 역 개수(=구간 이동 시간)만 기준으로 하며, 환승 대기 시간까지 더한 완전한 실제 소요 시간을 계산하는 것은 아니다.
- **1~8호선은 서울 도심 핵심 구간 위주로 간략화했다(4호선·9호선은 예외).** 1호선은 서울역을 중심으로 구로~청량리 구간만, 3호선은 구파발~오금(서울교통공사 구간)만, 5·6·7호선도 수도권 외곽으로 이어지는 지선·직결 구간은 대부분 뺐다. 모든 실제 노선을 전 구간 다루려면 이번 스펙 규모를 훨씬 넘어서는 데이터 조사가 필요해, 실제 환승이 몰려 있는 서울 도심 위주로 좁혔다. 4호선·9호선만 처음부터 전체 구간(과천선·안산선·진접선 포함)을 다뤘는데, 이미 예시로 쓰이던 평촌역·마곡나루역이 그 구간에 있었기 때문이다.
- **1~9호선에 속하지 않는 지명(판교역 등)은 손으로 정한 예시 조합만 지원한다.** 노선 데이터가 없는 지명까지 그래프 탐색으로 일반화하려면 모든 버스 노선의 실제 지리 데이터가 필요해 이번 범위를 넘어선다.
- **출발역·환승역 시각은 실제 열차 시각표가 아닌 추정치로 계산한다.** 서울교통공사 열차운행시각표(43만 행 CSV)는 인증키 없이 받을 수 있다는 걸 확인했고, 미리보기에는 코레일 계열 열차도 섞여 있어 커버리지가 처음 생각보다 넓을 수 있다는 것도 확인했다. 하지만 실제로 9호선·과천선 등 구간까지 포함하는지는 파일을 직접 받아봐야 확실한데, 자동화 도구로는 다운로드 자체가 걸리지 않았고, 역명이 아닌 역사코드 기준이라 별도 매핑 데이터까지 필요해 이번 스펙 규모를 크게 넘어선다. 대신 사용자와 상의해, 노선별로 알려진 실제 배차간격을 반영한 추정치로 개선했다.
- **환승 대기 시간(환승 열차 출발 예정)은 노선별 실제 배차간격을 참고한 추정치로 계산한다.** 4호선(사당 이북 기준 출퇴근 3분·평시 5분), 9호선(일반 기준 출퇴근 7분·평시 11분), 2호선(출퇴근 2분·평시 6분)은 검색으로 확인한 대략적인 실제 배차간격을 근거로 삼았다. 그 외 노선이나 버스는 근거를 찾지 못해 대략적인 값(출퇴근 6분·평시 10분)을 사용한다. 출퇴근 시간대는 07~09시, 18~20시로 가정한다.
- **지명 → 가까운 정류장 추천도 실제 지오코딩이 아닌 예시 데이터로 채운다.** 실제로 구현하려면 지명을 좌표로 바꾸는 지오코딩(예: 카카오 로컬 API)과, 그 좌표 주변의 정류장을 찾는 근접 정류소 조회(TAGO의 좌표기반근접정류소 목록조회 API)가 필요하다는 걸 확인했다. 두 기능 모두 실제로 존재하고 API 문서로 확인되지만, 각각 별도의 인증키가 필요하다. 이미 도착정보 API 인증키도 없는 상태에서 두 개의 키를 추가로 요구하면 이번 첫 결과물의 범위를 벗어나므로, 도착 정보와 같은 방식으로 미리 정해둔 지명-정류장 조합을 예시 데이터로 제공한다.

## Assumptions

- 환승 지점의 출발 예정 시각 목록(환승 지점마다 3개)은 배차간격이 일정하다고 가정해 등간격으로 계산한 값이며, 실제 열차/버스 지연이나 배차 변동은 반영하지 않는다.
- 지명-정류장 예시 데이터 조합(판교역/여의도/잠실역/합정 등)은 실제 위치 관계를 검증한 것이 아니라, 흐름을 보여주기 위한 예시로 구성한 것이다.
- 1~9호선의 역 이름과 순서는 위키백과 기준으로 확인했지만, 각 구간의 실제 소요 시간을 반영한 것은 아니다.
- 여러 노선을 동시에 지나는 역을 출발지나 목적지로 입력하면, 목적지가 그중 어느 한 노선이라도 출발지와 공유하는 순간 이미 환승 지점 자체이므로 "환승이 필요 없는 구간"으로 안내한다.
- 노선 순서를 아는 구간은 역 1개당 2분이 걸린다고 가정해 소요 시간을 추정한다. 손으로 정한 예시 조합(판교역·여의도 등 버스 구간)은 노선 순서 데이터가 없어, 역 간격 대신 미리 정해둔 대략적인 소요 시간 값을 사용한다. 둘 다 실제 배차·소요시간을 측정한 값이 아니다.
- 기존에 손으로 만든 "여의도→합정" 버스 경유 예시는, 여의도역·합정역이 이제 노선 그래프(5·9호선, 2·6호선)로 연결되면서 자동으로 대체됐다. 판교역은 노선 데이터가 없는 지명이라 예시 그대로 남아 있다.
- 환승 대기 시간(환승역 도착부터 다음 열차 출발까지)은 실제 배차표를 조회한 값이 아니라, 노선별로 검색해 확인한 대략적인 배차간격과 출퇴근·평시 구분을 반영한 추정치다.

## Off-limits for this work

- 환승 3회 이상인 경로 — 노선 그래프 탐색의 깊이를 2회로 제한했다.
- 1~9호선의 수도권 외곽 지선·직결 구간(예: 4호선 진접선 일부, 5호선 마천 지선 등 이번에 다루지 않은 부분) — 서울 도심 핵심 구간 위주로 좁혔다.
- 노선 그래프 탐색에서 환승 대기 시간까지 포함한 완전한 최단 시간을 계산하는 것 — 총 이동 역 수(구간 이동 시간)만 기준으로 최적 경로를 고르며, 환승 대기 시간은 비교에 넣지 않는 단순화다.
- 실제 라이브 API 연동(버스·지하철 도착정보, 카카오 지오코딩, TAGO 좌표기반근접정류소), 인증키 발급 및 관리 — 모두 사용자의 개인 계정으로 발급받아야 하는 부분이라 이번 작업 범위 밖이다.
- 예시 데이터에 없는 임의 지명 입력에 대한 처리(검색, 오류 안내 등) — 실제 지오코딩이 없는 상태에서는 의미 있게 다룰 수 없다.
- 계정, 즐겨찾기, 경로 저장 — PRODUCT.md에서 이미 두지 않기로 확정했다.
- 위치 자동 추적(GPS 기반 자동 알림) — PRODUCT.md에서 이미 사용자가 직접 확인하는 방식으로 확정했다.

## Deferred

- 1~9호선의 수도권 외곽 지선·직결 구간까지 노선 데이터 확장.
- 환승 3회 이상 경로 지원, 또는 환승 대기 시간까지 포함한 완전한 최단 시간 계산으로 전환.
- 실제 인증키 발급 후 라이브 API(버스·지하철 도착정보)로 전환.
- 카카오 지오코딩 API + TAGO 좌표기반근접정류소 API를 활용한 실제 지명 검색·근접 정류장 추천으로 전환.
- 지하철 운영사별(서울교통공사, 코레일, 서울시메트로9호선, 공항철도, 신분당선 등) 실제 라이브 API 연동 — 예시 데이터 단계에서는 운영사를 가리지 않지만, 실제 API로 전환하면 운영사마다 API가 다를 수 있어 별도 조사·연동이 필요하다.
- 서울교통공사가 인증키 없이 제공하는 열차운행시각표 파일을 실제로 내려받아 파싱하는 방식으로 전환 (다만 서울교통공사 관할 구간에 한해서만 커버 가능하다는 한계는 남는다).

## Remaining risks

- 지하철 운영사가 서울교통공사, 코레일(과천선 등), 서울시메트로9호선, 공항철도 등으로 나뉘어 있다는 게 이번에 확인됐다. 실제 라이브 연동 단계에서 이 운영사들이 각각 다른 API·인증키를 요구할 수 있고, 일부는 공식 공공 API가 아예 없을 수도 있다.
- 실제 인증키로 호출했을 때 문서와 다른 응답 형태나 예외 상황(정류소/역 ID 오류, 서비스 장애 등)이 나타날 수 있으며, 예시 데이터 기반으로 만든 화면 구조가 이를 그대로 수용하지 못할 수 있다.
- 개발계정 트래픽 제한(TAGO 기준 일 10,000회)이 실제 서비스 운영 단계에서는 충분하지 않을 수 있다.
- 실제 카카오 지오코딩 + TAGO 근접 정류소 조회로 전환하면, 지명이 모호하거나(동명 지명 여러 개) 근접 정류장이 여러 개 나오는 경우를 다뤄야 하는데, 이번 예시 데이터는 지명 하나당 정류장 하나로 단순화되어 있어 그 복잡도를 반영하지 못한다.
- 경로 비교는 총 이동 역 수만 기준으로 하고 환승 대기 시간은 반영하지 않기 때문에, 역 수는 더 적어도 환승 대기가 길어 실제로는 더 늦게 도착하는 경로가 추천될 수 있다. 실사용 정확도가 중요해지면 환승 대기 시간까지 포함한 계산으로 바꿔야 한다.
- 1~8호선을 서울 도심 핵심 구간 위주로 좁혀서, 수도권 외곽 지선·직결 구간의 역 이름을 입력하면 "예시 데이터에 없는 지명"으로 처리된다. 사용자가 또 다른 실패 사례를 보고할 수 있다.
